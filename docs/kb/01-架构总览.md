# 架构总览

## 1. 四个产物

| 产物 | 源码 | 作用 |
| --- | --- | --- |
| `GitRT.exe` | `src/gui/` | GUI 主程序（`-mwindows`）+ **全部 CLI 门面**（`--run` / `--ai` / `--squash` / `--restore` / `--tag-*` / `--release-*` / `--list-commands` / `--self-test`） |
| `GitRT.Shell.dll` | `src/shell/` | Win11 现代右键菜单扩展（`IExplorerCommand`），加载在 `dllhost.exe` 里 |
| `GitRT.ShellProbe.exe` | `src/shellprobe/` | "无资源管理器"验证工具：`--dump` / `--self-test` / `--activate` / `--shell-menu` / `--invoke` |
| `GitRT.CoreTests.exe` | `src/tests/` | 无窗口单元测试（CTest 用例 `core_selftest`），毫秒级、不需要桌面会话 |

CLI 门面与 GUI **共用同一条** `CommandSpec → BuildCommand → git_runner` 路径 —— 所以对 CLI 的
端到端测试等价于对菜单/参数面板逻辑的测试。这是全仓库最重要的一条测试策略。

## 2. 两个静态库（链接期强制分层）

| 库 | 源文件 | 谁可以链 |
| --- | --- | --- |
| `gitrt_core_tiny` | `core.cpp` `config.cpp` `command_spec.cpp` `json_util.cpp` `request_section.cpp` | **只有** `GitRT.Shell.dll` |
| `gitrt_core` | `src/core/*.cpp` 全部（**包含 tiny 的那几个，同一份代码编译两次**） | GUI / ShellProbe / CoreTests |

为什么这样切：Shell DLL 跑在 Explorer 的宿主进程里，**不许**有网络、不许起 git 进程、不许有
第三方运行时依赖。分层不靠自觉，靠**链接期**：Shell 只链 tiny，误用 `git_runner` / `ai_client`
会直接链接失败。**没有任何目标同时链接两个库**（否则同一份匿名命名空间状态会有两个实例）。

## 3. 一次点击的数据流

```
右键 → Explorer 建树(IExplorerCommand/IEnumExplorerCommand)
     → 点「GitRT」(menu.mode=app，cmdId=0) 或某个命令
     → SelectionContext 解析选区（零 git 调用，纯文件系统探测）
     → 共享内存请求段 Local\GitRT.Req.<pid>-<tick>-<seq>（路径 + 选项 JSON）
     → 直启 GitRT.exe --request-section <段名>（Broker 未运行时；有 Broker 就先走命名管道）
     → GUI 读段 → 定位命令 → 建参数面板（预填选区与 flags）
     → 用户点「执行」→ BuildCommand() 生成 argv → 进程内就地跑 → 结果写"运行结果"框
```

两个容易踩的点：

- **命名段不能"写完就关"**：段对象在最后一个句柄关闭时销毁，若 DLL 先关、GUI 后开就会
  `ERROR_FILE_NOT_FOUND`，表现为"点了菜单没反应"。`src/core/request_section.cpp` 用 FIFO
  保活最多 8 个句柄解决这件事。
- **外壳对子菜单项传 `IShellItemArray == nullptr`**：只按"空选区"裁剪会让整个子菜单空白。
  见 §4 的实测记录与 `src/shell/selection.h` 的粘性选区（TTL 5 s）。

## 4. 菜单形态

默认 `menu.mode = app`：右键里**只有一项「GitRT」**，点开就是主窗口，并把上下文切到你右键的位置。
`"menu.mode": "tree"` 可切回分层菜单（8 分组 + 可选直达项 + 可选内联开关），用来应付"我要直接右键执行"的用户。

菜单构建期（`GetTitle`/`GetFlags`/`GetState`/`EnumSubCommands`）**零 git 调用、预算 10 ms**，
实测 app 形态 ≈ 0.001 ms、tree 形态 ≈ 0.02 ms。状态一律来自：本地廉价探测
（`ProbeRepo`，只看 `.git` 下文件是否存在）+ 共享内存快照（Broker 未接入 → 状态"未知" → 乐观显示）。

## 5. Broker（还没做实）

`src/shell/snapshot_reader.*` 已经是"只读、无锁 seqlock"的读者实现，`src/shell/broker_client.*`
已经能往 `\\.\pipe\GitRT.<sid>.v1` 写一行 JSON。今天的实际路径是"检测不到 Broker → 直启 GUI"，
所以菜单永远可用；接上 Broker 只是把"直启"换成"转发 + 状态快照"。
