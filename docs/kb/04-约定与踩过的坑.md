# 约定与踩过的坑

本仓库的注释密度就是这么来的：每条"★ / 踩过 / 实测"都对应一次真实故障。改代码前先扫一遍这一页，
能省掉一次排查。

## 1. 跨进程 / 线程的对象交接：必须用 PostOwned

`src/gui` 里有大量"工作线程算好一个对象 → `PostMessageW` 交给 UI 线程接管"的写法。
Win32 消息是**异步**的：目标窗口可能已经销毁，`PostMessageW` 返回 `FALSE`，对象就没人接管 ——
项目里曾因此漏了 25 处泄漏（是当时的 `g++ -fanalyzer` 找出来的）。

```cpp
// 投递方：失败就地回收，成功才 release
PostOwned(hwnd, WM_GRT_TASK_LOG, std::make_unique<std::string>(out));

// 接收方：一律 unique_ptr 接管，**包括窗口正在销毁时要丢弃的分支**
case WM_GRT_TASK_LOG: {
    std::unique_ptr<std::string> line(reinterpret_cast<std::string*>(lp));
    if (st && line) AppendLine(st, ...);
    return 0;
}
```

**不要**写 `auto* p = new T(...); if (!::PostMessageW(...)) delete p;` —— 漏掉那个 `if` 就是必漏。
仓库已移除 `-fanalyzer` 选项，所以现在没有自动检查会替你抓这类泄漏，只能靠 review。

## 2. Win32 Edit 不认裸 LF

git 输出是 LF-only，`ES_MULTILINE` 的 Edit 直接塞进去会把所有行并成一行（实机 bug：提交历史三条
提交挤在一行）。所有多行文本必须过 `ToCrlf()`（`src/gui/ui_util.cpp`，幂等）。
断言在 GUI 自检里有一项"换行归一化：LF → CRLF"。

## 3. windres 不跟踪 #include，必须显式声明依赖

`.rc` 通过 `#include` 引入 `menu_strings.{zh,en}.rcinc` 与 `resource_ids.h`，而 windres 没有可靠的
`-MD`。不声明依赖的症状是"改了字符串片段，DLL 里还是旧串"，极难排查。两个 CMakeLists
（`src/gui` / `src/shell`）都用 `set_property(SOURCE ... APPEND PROPERTY OBJECT_DEPENDS ...)` 声明。

## 4. 自动化里弹模态框 = 挂死

自检/CI 里没人去点模态框，而 `MessageBoxW` **阻塞调用线程** —— 回归的表现不是"变红"而是
"永远不返回"（实测：分派缺映射时报告文件都没生成，任务挂了一百多秒）。
两条对策：`SuppressModalDialogs(true)`（自检开头调），以及"先断言映射实现了再调用分派"。

## 5. git 输出的分隔符：`for-each-ref` 不支持 `%x1f`

```
git log --pretty=format:%H%x1f%h%x1f%s          # 可以，%x1f = US 分隔符
git for-each-ref --format=%(refname)%x1f...      # ✗ 原样吐出字面量 "%x1f"
```
`for-each-ref` 只能用 `%09`（Tab）。且 subject 里可能再出现 Tab，所以要"只取前 N 个字段、
其余拼回 subject"（`src/core/tag.cpp` 与 `src/core/remote.cpp` 都这么处理）。

## 6. "不想连远端"必须显式传 `L"-"`

`LoadTags(..., remoteName)` 的 `remoteName` 传空串会被 `PickRemoteName()` 当成 `origin`，
于是开窗口时照样跑 `git ls-remote`，离线/坏网时开窗卡 6 秒。想跳过网络就传 `L"-"`。

## 7. 执行完必须**重读** `git status`

`WM_GRT_STATUS_RELOAD` 的 `wp` 决定行为：`wp=1` = 先 `RefreshRepoStatus()` 再刷视图；
`wp=0` = 只刷视图。命令跑完只发 `wp=0` 会显示**旧数据**（"执行完状态没变"）。

## 8. 互斥组（Radio）的默认值只在"没人显式选"时生效

否则会出现 `git reset --mixed --hard` 这种自相矛盾的 argv。`ExpandFlags()` 里用
`groupExplicit` 记录"组内是否有人被显式选中"。

## 9. 复选 + 可选值：勾选状态与输入内容必须分开存

`flags[key] = "1"/"0"` 与 `flags[key + ".value"] = 内容` 两个键。合成一个键就会出现
"填了内容被当成勾选"或"取消勾选把内容一起清掉"。未勾选时值**一律不进 argv**（有断言）。

## 10. 代理：git 只读 `http.proxy`，取消是"空串"不是 `--unset`

本机 git 2.56 实测：

| 配置 | 结果 |
| --- | --- |
| `-c https.proxy=<坏端口>` | **不生效**（照样直连） |
| `-c http.proxy=<坏端口>` | 立刻走代理并失败 |
| `http.proxy` 设为空串 | 不走代理，且**优先于**环境变量 `http_proxy` |
| `config --unset http.proxy`（键不存在时） | 退出码 **5** → 面板显示"执行失败"，可用户要的正是"没有代理" |

所以"取消代理设置"这条命令写的是 `git config [--global] http.proxy ""`。

## 11. 身份清单的 CLSID 不带花括号

`AppxManifest` 的 `com:Class/@Id` 与 `desktop5:Verb/@Clsid` 按 schema 必须是
`[0-9a-f]{8}-…-{12}` 形式，带 `{}` 会 `0x80080204` / `0xC00CE169`。`identity.cmake`
导出带括号的形式供 C++ 用。

## 12. 外壳给子菜单项传 `IShellItemArray == nullptr`

外壳顺序是"先 `EnumSubCommands` 建树 → 再逐项 `GetState(child, nullptr)`"。若把"空选区"当
"没有可用命令"裁剪，整个子菜单会**空白**。对策：选区未知 → 全量显示（真正的闸门在参数面板），
外加**进程内粘性选区**（TTL 5 s）供子项复用。回归用例是 `tools/test-all.ps1` 的 D4/D5 ——
纯进程内自检永远看不到这个 bug。

## 13. 共享内存请求段不能"写完就关"

命名段在最后一个句柄关闭时销毁。DLL 先关、接收方后开会拿到 `ERROR_FILE_NOT_FOUND`，
表现为"点了菜单没反应"。`request_section.cpp` 用 FIFO 保活最多 8 个句柄。

## 14. 行尾由 `.gitattributes` 定，别用编辑器整篇转换

源码/文档 LF，`.ps1` 与 `.rc`/`.rcinc`/`.reg` CRLF。整篇转换 =`整文件 diff`。

## 15. 文档改了要跑检查器

`python -X utf8 tools/check-docs.py`：查站内链接目标是否存在、表格列数是否一致
（未转义的 `|` 会让整行错位；两张表粘在一起会静默渲染歪）。它上线当天就抓出 2 条死链、
5 处未转义的 `|`、2 处表格结构损坏。

## 16. `Check(expr, msg)` 的实参求值顺序

消息里若调用会填 `err.message` 的函数，打印出来可能是空串（C++ 实参求值顺序未指定）。
先求值、再拼消息。
