# 调试与排错（出问题时按这个顺序看）

> 这一页是"症状 → 先看哪儿 → 常见真因"。所有结论都来自本仓库实际踩过的故障，
> 不是通用清单。加新症状时请**连同根因与修法**一起写，别只写"重启试试"。

## 1. 先看日志（比猜快十倍）

| 文件 | 位置 | 内容 |
| --- | --- | --- |
| 运行日志 | `%LOCALAPPDATA%\GitRT\logs\gitrt-YYYYMMDD.log` | `时间 [tid] [pid] 级别 类别 消息`，按天切分 |
| 配置 | `%APPDATA%\GitRT\config.json` | 扁平键值表（`flags.*` / `ai*` / `autoFetchMinutes` …） |
| AI 设置 | `<exe 同目录>\GitRT.ai.json` | 端点 / 模型 / Key（明文或 `dpapi:`） |
| GUI 自检报告 | `--self-test=<file>` 指定的文件 | `[PASS]/[FAIL]` 逐条，末尾是汇总 |
| Shell 自检报告 | `GitRT.ShellProbe.exe --self-test=<file>` | 菜单树 / 导出表 / 清单身份 |

日志级别默认 Info；`GRT_LOGI/W/E` 三个宏包在 `core.h` 里。要看更细的 git 调用参数，
把级别调到 Debug（`LogSetLevel`）—— 但**凭据永远不写日志**（`Redact()` 会把 URL 的 userinfo 抹成 `***@`）。

日志里的关键类别：
- `app`：启动、路径、版本；
- `git`：子进程 spawn 失败（含 Win32 错误码）与超时/取消；
- `gui`：状态读取、菜单请求落地、自动抓取失败；
- `shell.*`：菜单构建、Invoke 转发、请求段读写；
- `selftest`：自检结果与报告路径。

## 2. 症状 → 先看哪儿

| 症状 | 先检查 | 常见真因 |
| --- | --- | --- |
| 点右键菜单没反应 | 日志有没有 `shell.req` / `gui` 记录 | 请求段句柄提前关闭（`ERROR_FILE_NOT_FOUND`）；被安全软件拦 CreateProcess |
| 现代菜单看不见 GitRT | 用 `GitRT.ShellProbe.exe --dump <目录>` 看菜单树 | 包没注册；AppxManifest 里 CLSID 带了花括号（`0x80080204`） |
| 子菜单一片空白 | `--dump` 里子项状态是不是全 `HIDDEN` | 外壳给子项传 `IShellItemArray == nullptr`，按"空选区"裁剪了（见 04 §12） |
| 菜单里的字符串是空白/旧串 | `windres` 有没有重编译 `.res` | `.rc` 的 `#include` 没写进 `OBJECT_DEPENDS`（见 04 §3） |
| 改了字符串但 DLL 里还是旧的 | 同上；再确认改的是 `menu_strings.zh.rcinc` 而不是只改 GUI 的 `.rc` | 中英两份片段 + GUI 的 `.rc` **三处**都要加 |
| 参数面板一片空白/控件堆在左上角 | `stack` 里有没有 push 这个控件 | 新建控件忘了 `st->stack.emplace_back(ctl, h)` |
| 预览不随输入更新 | `WM_COMMAND` 有没有到面板 | `WM_SETTEXT` 不产生 `EN_CHANGE`（脚本里要手动补通知） |
| 执行完状态没变 | 结束时发的是 `wp=0` 还是 `wp=1` | `wp=0` 只刷视图，不重读（见 04 §7） |
| 提交历史里所有行挤成一行 | 文本有没有过 `ToCrlf()` | Edit 不认裸 LF（见 04 §2） |
| 深色模式下窗口一半亮一半暗 | 有没有调 `HandleEraseBkgnd` / `ThemeApplyToTableView` | `SetWindowTheme` 不传给子控件、窗口背景由窗口类画刷决定 |
| 窗口关掉后进程不退 | `WM_NCDESTROY` 有没有 `worker.join()` | 后台线程还活着，或停在 `MessageBoxW` 上 |
| 自检/CI 挂住不返回 | 报告文件生成了吗 | 模态框阻塞调用线程（见 04 §4）—— 自检开头必须 `SuppressModalDialogs(true)` |
| 标签订单里 hash 与 `rev-parse` 不一致 | `LoadTags` 有没有剥到提交 | 附注标签的 tag 对象 hash ≠ 提交 hash |
| 「标签列表」点执行弹"未实现" | `ActionOfInternal()` 有没有这一条 | 内部分派缺映射（见 [08 §4](08-GUI与窗口.md)） |
| 打开标签/发布窗口要等好几秒 | `LoadTags/LoadReleases` 有没有传 `L"-"` | 传空串会被当成 `origin`，照样跑 `git ls-remote`（见 04 §6） |
| AI 报"未配置 API Key"但明明填了 | 首选项状态行的"来源" | 环境变量 `GITRT_AI_*` 优先级最高；或文件不在 exe 同目录 |
| AI 连不上本地服务 | 端点是不是 `http://127.0.0.1:<端口>/v1/chat/completions` | 本机端点免 Key；写错路径会 404 |
| 推送/拉取卡住不动 | 是不是在等凭据输入 | `GIT_TERMINAL_PROMPT=0` 必须注入，否则无终端时永久阻塞 |
| `git status` 输出里中文路径是转义串 | argv 有没有 `-c core.quotepath=false` | 状态查询专用，别加到别的命令上 |

## 3. 三类"看起来是 bug、其实是设计"的行为

1. **`--run <internal-key>` 退 1 且什么都不执行**：`ExecKind::Internal` 的形态是窗口，CLI 里如实报告
   `note=internal command (needs the GUI)` + `exit=1`。脚本据此判断"没跑"是对的，不是失败。
2. **`--ai` 对内部命令报 `needs_gui=1` + `executed=0` + exit=1**：同上，方案被接受但没有 argv。
3. **未知选项被"忽略并提示"而不是报错**：`flags` 是白名单，未登记的 key 不进 argv，但在
   `warnings` 里点名 —— 这样模型多给一个选项不会让整条命令失败。

## 4. 效率工具：不用开窗口就能验证

```powershell
# 只看会构造出什么 argv（不执行）：最快验证命令表/模板改动
build\debug\src\gui\GitRT.exe --run adv.proxy-set --param port=10808 --cwd <repo> --dry-run --out o.txt

# 命令表快照：新 key 有没有进表、flag 列表对不对
build\debug\src\gui\GitRT.exe --list-commands --out cmd.txt

# 菜单树（不需要资源管理器）
build\debug\src\shellprobe\GitRT.ShellProbe.exe --dump <目录>

# 纯函数断言（秒级，无窗口）
build\debug\src\tests\GitRT.CoreTests.exe
```

## 5. 定位"到底是哪一层坏了"

按这条链从下往上试，坏在哪一层一目了然：

```
命令表(CommandSpec) → BuildCommand → argv          ← --dry-run 就能验
        ↓
git 进程(git_runner) → 真实输出                     ← --run 不加 --dry-run
        ↓
GUI 面板/窗口 → 用户看到的东西                      ← --self-test / demo 脚本
        ↓
Shell 菜单 → 右键里那一项                           ← ShellProbe --dump / --invoke
```

哪一层先出问题就修哪一层，**别跨层猜**：参数错了改命令表或校验，argv 对了但结果不对就是 git 语义问题，
窗口里显示不对才是 GUI 的问题。
