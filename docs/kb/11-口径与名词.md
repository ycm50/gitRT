# 口径与名词表（别用错词）

> 这个仓库里几个词经常被混用，而它们对应的代码与后果完全不同。写代码、写提交信息、
> 写文档前先对一遍口径 —— 词用错了，读的人会去改错的文件。

## 1. 核心名词

| 词 | 指什么 | 不是指什么 |
| --- | --- | --- |
| **命令（command）** | 命令表里的一条 `CommandSpec`（`id` + `key` + 模板） | 不是某次执行 |
| **选项（flag）** | `FlagSpec`：复选框/单选/值型，白名单内、持久化在 `flags.*` | 不是 `git config` 的配置项 |
| **参数（param）** | 面板里那个输入框（`ParamKind` + `paramKey`），进 `{paramKey}` 占位符 | 不是选项的值（`ToggleValue` 的 `.value` 是选项的值） |
| **执行（run）** | 走 `BuildCommand` → `git_runner` 真跑一次 | 不是"打开窗口" |
| **内部命令（Internal）** | `ExecKind::Internal`：没有 argv，只开窗口/写配置/起终端 | 不是"未实现" |
| **专用窗口** | 那 5 个由命令打开的全功能窗口（合并提交/还原/远端/标签/发布） | 不是文本窗口/进度窗口 |
| **查看类命令** | `inspect.log / inspect.diff / inspect.filelog`：面板里自动显示并 2.5 s 刷新 | 不是所有只读命令 |
| **就地执行** | 参数面板里跑，结果显示在「运行结果」框（`RunBuiltCommandOn`） | 不是进度窗口 |

## 2. 三个"状态"别混

| 说法 | 含义 | 在哪 |
| --- | --- | --- |
| 仓库状态 | `git status --porcelain=v2` 的解析结果（暂存/修改/未跟踪/冲突计数） | `App().status` |
| 菜单状态 | 菜单项是 ENABLED/HIDDEN/DISABLED（`EXPCMDSTATE`） | `src/shell/explorer_command.cpp` |
| 任务状态 | 一次执行的结果（ok/cancelled/exitCode/耗时） | `TaskOutcome` / `TaskSummary` |

"状态没刷新"通常指第一个；"菜单灰了"指第二个；"执行显示失败"指第三个。

## 3. "危险"的三个级别与本仓库的用词

| `Danger` | 界面表现 | 例子 |
| --- | --- | --- |
| `Safe` | 直接执行 | 拉取、抓取、暂存 |
| `Careful` | 参数面板顶部一行提示；不加二次确认 | 推送、合并、还原到提交、**取消代理** |
| `Destructive` | 第一次点「执行」只把按钮换成「确认执行（不可撤销）」，10 s 内不再点就解除 | 撤销改动、清理未跟踪、硬重置、合并提交 |

选项级的 `danger=true`（`FlagKind::Dangerous`，如 `--no-verify`、`-x`、`-D`）也会让按钮进入确认态。

**文档里不要写"危险操作需二次确认"了事**：要写清是哪一级、以及哪些选项会把它升级。

## 4. 涉及 git 的用词

| 我们说 | 对应的 git 事实 |
| --- | --- |
| 上游 / upstream | `branch.<name>.merge` + `branch.<name>.remote` |
| 远端基线 | 上游 ref 指向的那条提交（提交历史里【远端】那一段） |
| 本地新增 | 以远端基线为基、往上累加的提交（`origin/main +2`） |
| 领先/落后 | `git status` 的 `branch.ab +N -M` |
| 浅克隆 | `clone --depth`（部分克隆是 `--filter`，**不是**浅克隆） |
| 合并到基线 | 合并提交（squash）时勾到根提交：新提交**没有父**，仓库之后没有上游 |
| 强制推送（安全版） | `--force-with-lease`（不是 `--force`；面板里可带 `<引用名>[:<期望值>]`） |

## 5. CLI 输出字段（脚本靠它断言，改名就是破坏契约）

`--run` 输出 `key=value` 行：`key` / `cwd` / `repo` / `git` / `requires_repo` / `paths` /
`argv0..N` / `note` / `cmdline` / `step0_exit..` / `exit`；
`--list-commands` 输出 `[GitRT-CMDLIST]` + `count=N` + 每行 `CMD|key|group|requiresRepo|exec|param|flags`；
`--squash` 有 `touches_root=` / `base=`；`--restore` 有 `needs_extra_confirm=`；
`--remote-info` 有 `ahead=` / `behind=` / `local_only=`。

改动这些字段要同步 `tools/test-*.ps1`；**新增字段是兼容的，改名不是**。

## 6. 中文 / 英文的维护点

| 字符串类别 | 文件 | 语言 |
| --- | --- | --- |
| 命令标题 / 分组名 / 选项标签 | `src/core/menu_strings.zh.rcinc` + `menu_strings.en.rcinc` | 中 + 英（两份**片段**，被 GUI 与 Shell 共用） |
| 参数标签 `IDS_PARAM_*` | `src/gui/resources.rc`（只有中文 `STRINGTABLE`） | **只有中文** |
| 界面专有串（按钮/标题/提示/状态） | `src/gui/resources.rc` 的两个 `STRINGTABLE` | 中 + 英 |
| 代码注释与错误消息 | 源码 | 只有中文（错误消息要能直接给用户看） |
| 日志正文 | 源码 | 英文标识符 + 中文说明混排 |

**已知缺口（2026-11 记录）**：`IDS_PARAM_*` 这一组只有中文，英文界面下参数标签会显示成
`?3100` 这类占位符（`Str()` 找不到资源时的兜底）。它们不是这次引入的，但**加新参数类型时别跟着漏**：
要么补进英文 `STRINGTABLE`，要么接受这个占位符并在文档里说清楚。

新增一条命令/选项（走 `menu_strings.*.rcinc`）必须**中英两份都加**；只加中文，英文界面里就是空白。
