# 构建与测试

## 1. 工具链与预设

主工具链是 **MSYS2 UCRT64（MinGW-w64 g++）**，不是 MSVC（决策 D4）。CMake ≥ 3.25 + Ninja，
`-fno-rtti`，静态链接 CRT，**零第三方依赖**（连测试框架都是自写的 `src/tests/check.h`，约 50 行）。

```powershell
cmake --preset ucrt64-debug      -DCMAKE_MAKE_PROGRAM=A:/msys64/ucrt64/bin/ninja.exe
cmake --build build/debug
cmake --preset ucrt64-release    -DCMAKE_MAKE_PROGRAM=A:/msys64/ucrt64/bin/ninja.exe
cmake --build build/release
```

预设见 `CMakePresets.json`（二进制目录固定 `build/debug` / `build/release`）。

构建期选项：

| 选项 | 默认 | 作用 |
| --- | --- | --- |
| `GRT_WERROR` | OFF（**CI 固定 ON**） | 把编译告警当错误 |
| `GRT_DEV_REGISTER` | Debug ON / Release OFF | 编进 `DllRegisterServer`/`DllUnregisterServer`（传统注册测用） |
| `GRT_SHELL_PROBE` | OFF | 把菜单构建期计时/探针日志编进 Shell DLL |
| `GRT_BUILD_TOOLS` | ON | 构建 `GitRT.ShellProbe.exe` |
| `GRT_BUILD_TESTS` | ON | 构建 `GitRT.CoreTests.exe` 并注册进 CTest |

## 2. 四层测试（改动**必须**落到正确的层）

| 层 | 在哪 | 跑法 | 什么时候用 |
| --- | --- | --- | --- |
| ① 无窗口单元测试 | `src/tests/core_tests.cpp`（链接 `gitrt_core`，**不许**用 `gui.h`） | `ctest -R core_selftest` / 直接跑 exe | 纯函数、argv 构造、参数校验、JSON、AI 解析与闸门、端点判定 |
| ② GUI 自检 | `src/gui/main.cpp` 的 `RunSelfTest()` | `GitRT.exe --self-test=<file>` | 需要真窗口/真资源/真 git 仓库：参数面板 N/N 可创建、图标、执行后状态刷新、远端/还原/标签 |
| ③ CLI 端到端 | `tools/test-*.ps1` | `pwsh -File tools/test-remote.ps1 -Exe …` | 真 git 仓库上的命令行行为（远端/合并提交/克隆/标签发布/安装卸载） |
| ④ Shell 自检 | `GitRT.ShellProbe.exe --self-test` / `--dump` | 见 CI 步骤 | COM 菜单树、导出表、清单身份一致性 |

判红标准统一：输出里有 `[FAIL]` 或结果行不是 `N 通过 / 0 失败`，或者退出码非 0。

**别把纯函数断言塞进 ②**：它要起 GUI、要等窗口、要读 txt；放 ①秒级就能跑，失败直接打在 stdout。

### 2.1 需要"外部程序在场"的路径

用桩 + 环境变量注入，不要因为"本机没装 gh"就 `[SKIP]`（等于那段代码从没被测过）：
```powershell
$env:GITRT_GH_EXE = "$PWD\tools\fake-gh.bat"
build\debug\src\gui\GitRT.exe --release-list --out rel.txt --cwd <repo>
```

### 2.2 GUI 级"真点按钮"脚本（本地跑，不进 CI）

`tools/demo-*.ps1` 会用 `SendMessage` 驱动真实窗口（点按钮、勾复选框、回确认框），
例如 `demo-live-panel.ps1`（参数面板自动显示 + 就地输出）、`demo-squash.ps1`（合并提交窗口）、
`demo-remote.ps1`（远端窗口）、`demo-taskbar-icon.ps1`（图标像素哈希比对）。
它们需要交互式桌面会话，所以只在本地跑。

## 3. CI（`.github/workflows/build.yml`）

- **只有 `workflow_dispatch`**（push/PR 都不自动跑）：这条流水线的终点是创建 GitHub Release，
  发布是产品决策，不该因为推了代码就自动发版。手动触发时 `tag` 必填。
- 矩阵：Debug + Release 两个配置都构建（`GRT_WERROR=ON`）+ CTest + GUI 自检 + Shell 自检/dump；
  功能套件只在 Release 那一路跑（与构建类型无关，跑两遍只是重复最慢的一段）。
- `package` job **复用** build job 的 Release 产物（不重装工具链、不重建），只做组装 + 安装/卸载端到端。
- `release` job 的 `needs: [build, package]` 且显式检查两者 `result == 'success'`：
  构建没全绿**不会**创建 tag / Release。同名 tag / Release 一律**覆盖**（tag 用 `-f` + `push --force`，
  Release 先 `gh release delete --yes` 再重建）。
- ccache 缓存 `$RUNNER_TEMP/ccache`，Debug/Release 各一份 key，接成
  `CMAKE_{C,CXX}_COMPILER_LAUNCHER`。

### 3.1 CI 踩过的三个坑（都写在 workflow 顶部的注释里）

1. **不要把原生命令接进 `Select-Object -First N`**：管道被提前关闭会把 g++/cmake 杀掉 →
   退出码非 0，而 GitHub 的 pwsh 包装器把 `$LASTEXITCODE` 当步骤退出码 → 步骤直接失败。
   先取到变量再截行，并在步骤末尾 `$LASTEXITCODE = 0`。
2. **别猜 MSYS2 装在哪**：`setup-msys2` 有官方 output `msys2-location`；它默认不把工具加进 PATH，
   所以统一用 `$env:UCRT64_BIN` 的绝对路径（`.github/actions/setup-ucrt64` 里只有一份）。
3. **`tools/check-docs.py` 不进 CI**：它打印中文，runner 的 stdout 是西文代码页 →
   `UnicodeEncodeError` 让步骤 10 秒失败。本机跑用 `python -X utf8 tools/check-docs.py`。

## 4. 可复现构建

设了 `SOURCE_DATE_EPOCH` 就启用：PE 头 `TimeDateStamp` 改用它，并用 `-ffile-prefix-map`
抹掉产物里的绝对构建路径（源码里没有 `__DATE__`/`__TIME__`，已 grep 确认）。
同源码 + 同 epoch → 产物 SHA256 **逐字节一致**（实测两次独立构建）。不设时行为与以前完全一样。

## 5. 打包与安装

```powershell
pwsh -File packaging/scripts/build-release.ps1 -Config Release   # → build/dist/GitRT-<ver>-win-x64(.zip)
pwsh -File packaging/scripts/dev-install.ps1 -Config Release     # 铺文件 + 免签名 loose 注册 + 重启 explorer
pwsh -File packaging/scripts/dev-uninstall.ps1
pwsh -File packaging/scripts/dev-reload.ps1                      # 只重启 explorer（改了 DLL 后）
```

- **身份的唯一真相源是 `packaging/identity.json`**：`GRT_VERSION`、exe/DLL 的 `FileVersion`、
  MSIX 清单、`clsid_values.h` 全部由它派生。它被登记进 `CMAKE_CONFIGURE_DEPENDS`，
  改它会触发重新 configure（以前不会 → "改了版本号却不生效"）。
- `CLSID` 在清单里**必须不带花括号**（带 `{}` 会 `0x80080204`）。
- 面向用户的 `install.ps1` 装到 **`pwd` 所在盘符根目录的 `\gitRT`**（绿色安装），
  并写 `HKCU\Software\GitRT`（`InstallDir`/`Version`/`ExePath`/`UninstallString`）。
- ★ **稀疏包内容单独放 `<安装目录>\master\`**（`AppxManifest.xml` + `Assets\` + `GitRT.Shell.dll`），
  `Add-AppxPackage -Register … -ExternalLocation <安装目录>\master`；**`GitRT.exe` 必须留在 master 之外**。
  原因：右键经稀疏包 COM surrogate 拉起 GUI 时进程带包身份，exe 若在 ExternalLocation 内，
  任务栏图标会改取清单的 `Square44x44Logo.png`（透明底小图）→ 显示成空白方块。
  实测与已排除的六种修法见《支持矩阵》§2.1b 与《技术实现设计》§9.5c。
- 卸载会先把 `GitRT.ai.json` 备份到 `%APPDATA%\GitRT\uninstall-backup-<时间>\`，重装自动恢复。

## 6. 提交前自检（本地最短路径）

```powershell
cmake --preset ucrt64-debug -DGRT_WERROR=ON && cmake --build build/debug
ctest --test-dir build/debug --output-on-failure
build\debug\src\gui\GitRT.exe --self-test=build/selftest.txt
python -X utf8 tools/check-docs.py
```
