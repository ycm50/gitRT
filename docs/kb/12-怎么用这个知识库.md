## 3. 新人上手顺序（约 40 分钟）

1. [01 架构总览](01-架构总览.md)：四个产物、两个静态库、一次点击的数据流（10 分钟）；
2. [02 命令表](02-命令表与参数面板.md)：为什么"加命令=加一行表"（10 分钟）；
3. [03 构建与测试](03-构建与测试.md) §1–§2：把 `cmake --preset ucrt64-debug` 跑通、`ctest` 跑绿（10 分钟）；
4. [04 踩过的坑](04-约定与踩过的坑.md) 前 10 条：这些是最容易重复踩的（10 分钟）；
5. 想做界面再读 [08](08-GUI与窗口.md)，想安全相关再读 [05](05-安全边界.md)。

## 4. 这些文档与设计文档的分工

| 想知道 | 看 |
| --- | --- |
| 需求为什么这样定、权衡过程 | `docs/产品设计.md`（权威） |
| 技术方案、数据结构、模块契约 | `docs/技术实现设计.md`（权威） |
| **改这个仓库要怎么做、会踩什么** | `docs/kb/*`（本目录） |
| 某项能力在本机实测到什么程度 | `docs/支持矩阵.md` |
| 还有哪些已知缺口、怎么补 | `docs/改进规划.md` |

设计文档是"为什么"，kb 文档是"怎么做"。两边说法冲突时以设计文档为准，
并**回头修 kb 文档**（它才是查库时最先被读到的那一份）。
