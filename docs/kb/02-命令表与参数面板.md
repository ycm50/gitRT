# 命令表与参数面板

## 1. 核心思路

命令的**标题 / 可用性 / 选项白名单 / 参数 schema / 危险级别 / argv 模板全部是数据**
（`src/core/command_spec.h` 的 `CommandSpec`）。代码只做通用解释：

- 菜单（`src/shell/menu_model.cpp`）遍历同一张表建树；
- GUI 命令列表与参数面板（`src/gui/app_window.cpp` / `src/gui/param_panel.cpp`）遍历同一张表建控件；
- AI 提示词（`src/core/ai_client.cpp` 的 `BuildPlannerSystemPrompt`）也是遍历这张表生成的；
- 唯一的 argv 出口是 `BuildCommand()`（`src/core/command_builder.cpp`）。

**所以"新增一条命令"= 加一行表 + 一条 argv 模板（+ 若干资源串）**，不写 UI 代码。

## 2. 字段速查（`CommandSpec`）

| 字段 | 含义 | 常见取值 |
| --- | --- | --- |
| `id` | 稳定数字 ID，**只增不改** | 见 `src/core/resource_ids.h`，按分组分段（1xxx 仓库/提交，2xxx 同步/查看，3xxx 分支，4xxx 查看，5xxx 储藏，6xxx 高级，7xxx 应用） |
| `key` | 稳定字符串 key（CLI `--run` 用） | `"adv.proxy-set"` |
| `group` | 菜单分组 | `GroupId::Repo/Commit/Sync/Branch/Inspect/Stash/Advanced/App` |
| `titleRes` | 标题资源 ID | `IDS_CMD_*` |
| `applies` | 选择类型位掩码 | `kSelFile/kSelDir/kSelBg/kSelMulti/kSelAny` |
| `requiresRepo` | 非仓库场景是否可用 | 只有 `repo.*` / `app.*` / `adv.proxy-*` 是 `false` |
| `danger` | `Safe / Careful / Destructive` | `Destructive` 会让参数面板强制二次确认 |
| `param` / `paramSource` / `paramKey` | 面板要收集什么参数 | `ParamKind`；`paramKey` 是模板里 `{key}` 的名字 |
| `exec` | 怎么执行 | `Cli`（直接跑）/ `CliPanel`（先弹参数面板）/ `CliStream`（长任务、可取消）/ `Internal`（GUI 内部动作，不产生 argv） |
| `flags` / `flagCount` | 选项白名单 | 非 White-list 的 key 一律被忽略 |
| `argvTemplate` | argv 模板 | `"git config {scope} http.proxy {port}"`，多步用 `" ; "` |

### 2.1 `FlagKind` 五种

| kind | 面板形态 | argv 行为 |
| --- | --- | --- |
| `Toggle` | 复选框 | 勾上 → `gitArg` 整个进 argv |
| `Radio` | 单选（`radioGroup` 内互斥） | 组内只有选中的那个进 argv；**显式选过就不再套默认值**（避免 `--mixed --hard` 同时出现） |
| `Value` | 只有输入框，**没有勾选框** | 填了值才进 argv，`gitArg` 里的 `{v}` 被替换 |
| `Dangerous` | 复选框 | 同 Toggle，但「执行」需二次确认 |
| `ToggleValue` | 复选框 + **同一选项下方**的值输入框（未勾选时灰掉） | 勾上 + 留空 → 发纯开关（`--force-with-lease`）；勾上 + 有值 → `--force-with-lease=<值>`；**未勾选时值一律不进 argv** |

值存在 `flags[key]`（`"1"/"0"`）与 `flags[key + ".value"]`（内容）两个键里，互不覆盖 ——
这条约定 `src/core/command_builder.cpp` 与 `src/gui/param_panel.cpp` 必须一致。

### 2.2 模板里的占位符

| 占位符 | 展开成 |
| --- | --- |
| `{flags}` | 按表内声明顺序展开的 flag 片段 |
| `{paths}` | `-- <路径…>`（空选区时整段消失） |
| `{paramKey}` | **校验/规范化之后**的参数值（不是原始输入，见下） |
| `{scope}` | 勾了 `global` 选项就放 `--global`，否则**整个消失** |
| `{empty}` | 一个空字符串 argv 元素（用于 `git config key ""` 这种"显式清空"） |

`{scope}` / `{empty}` 是为"`--global` 必须出现在 `config` 之后、键名之前"这类**位置敏感**参数准备的：
表内 flag 只能追加在 `{flags}` 处，表达不了位置。

## 3. 新增一条命令的完整清单

以 `adv.proxy-set`（2026-11 新增）为完整样例，顺序就是照着做：

1. **资源 ID**（`src/core/resource_ids.h`）
   - 命令标题：`IDS_CMD_ADV_PROXY_SET 2608`（规则：`2000 + (id - 1000)`）
   - 选项标签：`IDS_FLAG_GLOBAL 3057`（3000 段）
   - 参数标签：`IDS_PARAM_PROXY_PORT 3107`（31xx 段，放 `src/gui/resources.rc` 的中英两段）
2. **选项数组**（`src/core/command_spec.cpp` 匿名命名空间）
   ```cpp
   constexpr FlagSpec kProxyScopeFlags[] = {
       {"global", nullptr, FlagKind::Toggle, nullptr, IDS_FLAG_GLOBAL, /*defaultOn=*/true, false},
   };
   ```
   `gitArg = nullptr` = 纯 UI 开关：它不直接进 argv，而是由 `BuildCommand` 读出来决定 argv 形状。
3. **表项**（`kCommands[]`）
   ```cpp
   C(1608, "adv.proxy-set", GroupId::Advanced, IDS_CMD_ADV_PROXY_SET,
     kSelAny, /*requiresRepo=*/false, Danger::Safe, ParamKind::ProxyPort, ParamSource::None, "port",
     ExecKind::CliPanel, kProxyScopeFlags, 1, "git config {scope} http.proxy {port}"),
   ```
4. **参数类型**（如果需要新的 `ParamKind`）
   - `command_spec.h` 加枚举值；
   - `command_builder.cpp` 的 `switch (spec.param)` 加校验分支，**并在那里把 `paramValue` 规范化**
     （`std::wstring paramValue` 是可写的，`{port}` 展开时用的就是它）；
   - `src/gui/param_panel.cpp` 的 `ParamLabelRes()` 加标签映射，必要时加输入框样式
     （例如 `ES_NUMBER`）；
   - `src/tests/core_tests.cpp` 的 dry-run 循环里给这个 kind 填一个合法样例值。
5. **字符串**（三处都要加，否则英文界面/右键菜单里是空白）
   - `src/core/menu_strings.zh.rcinc`（中）+ `menu_strings.en.rcinc`（英）：标题与选项
   - `src/gui/resources.rc` 的中英两个 `STRINGTABLE`：参数标签
   - 这两个 `.rcinc` 是**片段**（只有 `KEY "value"` 行，不含 `STRINGTABLE` 包裹）
6. **审计改动的后果**
   - `gitrt_core_tiny` 也会编 `command_spec.cpp` → Shell DLL 里菜单立刻多一项；
   - AI 系统提示词自动包含新 key（不需要改提示词代码）；
   - 若要开专用窗口而不是拼 argv，走 `OpensDedicatedWindow()`（`src/gui/internal_commands.cpp`），
     **不要在参数面板里另抄一份名单**（抄漏过一次：标签列表/发布列表点执行弹"未实现"）。
7. **验证**
   ```powershell
   gitrt --list-commands --out cmd.txt        # 新 key 出现、flag 列表正确
   gitrt --run adv.proxy-set --param port=10808 --cwd <repo> --dry-run --out o.txt
   ./build/debug/src/tests/GitRT.CoreTests.exe          # argv 形状断言
   GitRT.exe --self-test=build/selftest.txt             # "参数面板 N/N 可创建"
   ```
8. **文档**：`README.md` 的能力表、`CHANGELOG.md` 的「新增」、`docs/技术实现设计.md` §3.5 的命令表、
   `docs/产品设计.md` 的需求表。跑一次 `python -X utf8 tools/check-docs.py`。

## 4. 参数面板的行为约定（`src/gui/param_panel.cpp`）

- **实时预览**：任何输入变化（`EN_CHANGE`/`BN_CLICKED`/下拉选择）都重新 `BuildCommand`，
  预览框里是**真正会执行的 argv**（`git` 前缀由 `BuildDisplayText` 补上）。
- 构造失败时预览框显示中文错误、**「执行」按钮禁用** —— 错误在构造期暴露，不留到 git 报错。
- **就地执行**：结果写在「将执行的命令」下面的「运行结果」框里，运行中按钮变「取消」，
  不再另开进度窗口；结束后 `WM_GRT_STATUS_RELOAD(wp=1)` 让主窗口重读 `git status`。
- **查看类命令**（提交历史/查看差异/文件历史）选中即显示内容，每 2.5 s 自动刷新。
- `Danger::Destructive` 或勾了 `Dangerous` 选项 → 第一次点执行只把按钮变成「确认执行（不可撤销）」，
  10 秒内不再点就自动解除。
- 打开专用窗口的命令（标签/发布/合并提交/还原/远端）在这里是**启动器**：
  预览显示"由 GitRT 内部处理"，「执行」保持可用（否则参数没填就永远点不进窗口）。
- 不需要仓库的命令（`repo.clone` / `repo.init` / `adv.proxy-*`）：工作目录取**选中的目录**
  或字面 `--cwd`，不会退化成外层仓库根。

## 5. 命令表当前规模

42 条（含 14 条 `ExecKind::Internal`）。分组与编号见 `src/core/command_spec.cpp` 的
`kCommands[]`；GUI 自检会断言"每个 Internal 命令都有去向"，新增 Internal 命令忘写分派会让自检变红
（`ActionOfInternal` 是唯一一份映射，且 `ExecuteInternalCommand` 的 switch **故意没有 default** ——
漏一个枚举值直接编译失败）。
