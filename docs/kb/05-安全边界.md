# 安全边界

## 1. git 永远不经过 shell

所有 git 调用都是 `CreateProcessW` + argv 数组（`src/core/git_runner.cpp`），参数经白名单校验
（分支名 / 远端名 / 修订表达式 / URL / 端口号）。没有命令注入面：

- 子进程只继承 3 个 stdio 句柄（`PROC_THREAD_ATTRIBUTE_HANDLE_LIST`），不继承其它可继承句柄；
- 外面套 Job Object + `KILL_ON_JOB_CLOSE`：取消/超时会连同整棵进程树一起结束，
  不留孤儿 `ssh` / credential helper；
- stdout / stderr 各用一个读线程（只读一个会在另一个填满 64KB 管道时把 git 卡死）；
- 环境变量白名单化：先删 `GIT_DIR` / `GIT_WORK_TREE` / `GIT_OBJECT_DIRECTORY` / `GIT_TRACE*` 等宿主
  泄漏变量，再注入 `GIT_TERMINAL_PROMPT=0`（必需，否则无终端时永久阻塞）、`LC_ALL=C`
  （稳定英文输出，便于错误映射）；状态查询额外加 `GIT_OPTIONAL_LOCKS=0`。

## 2. `CommandSpec` 是唯一的写操作出口

- 菜单 / 参数面板 / AI 三条路径**共用** `BuildCommand()`；
- `flags` 只接受 `FlagSpec` 表内的 key（未登记的 key 被**忽略并提示**，不是报错）；
- 值型参数在构造期校验（`IsValidBranchName` / `IsValidUrl` / `IsValidRevision` / `NormalizeProxyPort`），
  宁可在这里拦下，也不要让用户看到 git 那句难懂的报错。

## 3. AI 不能执行任意命令

- 模型只产出"从命令表里选哪条 + 参数 + 选项"的结构化计划，**永远不执行 AI 生成的命令行**；
- 未知 key 直接拒绝；未知选项忽略并提示；
- 查看类需求允许模型直出**只读** git 命令行，走 `ParseReadOnlyGitCommand()` 白名单
  （`status/log/show/diff/branch/remote/tag -l/rev-parse/describe/shortlog/blame/for-each-ref/
  ls-files/config --get*/stash list/reflog`）；写操作一律拒绝；
- 计划的危险级别由命令表的 `danger` + 选项的 `danger` 共同决定，危险时要用户在模态框里确认；
- Internal 命令（首选项/自检/合并提交/标签发布/提交历史）**不再被拒**，而是标记 `needsGui`，
  点「执行」走与菜单同一个分派打开窗口；CLI 侧如实报告 `needs_gui=1` + `executed=0` + exit=1。

## 4. 提示词里到底发出去什么

只有：仓库路径、当前分支名、最多 20 个已选文件的路径、用户输入的自然语言。
**不发文件内容、不发 diff、不发提交信息正文**。查看类命令的输出只显示在本地界面，不回传模型。

## 5. API Key

| 模式 | 落盘 | 说明 |
| --- | --- | --- |
| 明文（默认） | `<exe 同目录>\GitRT.ai.json` 的 `apiKey` | 产品决策：方便直接查看/修改；任何能读该目录的进程都能读到 |
| DPAPI 加密 | 同文件，值是 `dpapi:<base64>` | `CryptProtectData` 按当前用户；换用户/换机器解不开（提示重填，不清空文件） |
| 不落盘 | — | `apiKey` 留空，走 `apiKeyEnv` 指定的环境变量（默认 `DEEPSEEK_API_KEY`） |

保证：**凭据永不写日志**；界面不回显 Key 本身；远端地址里的 userinfo 显示为 `https://***@host/…`；
`.gitignore` 覆盖 `GitRT.ai.json` / `*.ai.json` / `*.pem` / `*.key` / `.env` / `*.pfx`；
加密失败时 **fail-closed**（不写 Key 并报失败，绝不悄悄回退成明文）。
优先级：`GITRT_AI_*` 环境变量 > `GitRT.ai.json` > `config.json` 的 `ai*` 键 > 内置默认。

**本机端点免 Key**：`IsLoopbackEndpoint()` 认 `localhost` / `127.0.0.0/8` / `[::1]`（含 `user:pass@`
前缀与无 scheme 写法），此时 Key 留空也能用（Ollama / LM Studio / vLLM / llama.cpp server）。
**明文过网告警**：`IsInsecureRemoteEndpoint()` = `http://` 且非本机 → 保存/测试时弹一次确认
（默认按钮"取消"），状态栏常驻提醒；程序不禁止（内网代理是真实用法），但不会让你不知情。

## 6. 我们**不**覆盖的 git 配置

`core.autocrlf` / `core.symlinks` / `core.fileMode` / `http.proxy` / `credential.*` / `user.*` /
`commit.gpgsign` / `pull.rebase` —— 这些是用户的仓库语义，**任何覆盖都会造成"CLI 和我预期不一致"**。
两个例外：

1. 状态查询时注入 `-c core.quotepath=false`（只影响输出编码）；
2. 用户**显式**点「设置代理…/取消代理设置」（`adv.proxy-set` / `adv.proxy-unset`）时——
   那条 `git config` 命令本身就是他要执行的东西，且预览里一字不差地写着带不带 `--global`。

## 7. 信任边界（写清楚，避免误解）

1. AI 服务端在信任边界之外：它看得到你发出的提示词；模型回复是**不可信输入**（只解析、不执行）。
2. 不是沙箱：程序以你的用户身份跑 git，仓库里的钩子、`core.pager` 之类配置仍可能做事情 ——
   与直接在终端跑 git 等价。
3. 本机即信任：能读写 exe 所在目录的进程可以读到明文 Key（除非启用 DPAPI）。
4. 不在范围：攻击者已能以你的身份运行代码、物理接触、第三方服务自身漏洞、你自己配的 git 钩子行为。

## 8. 安全相关的断言在哪

`core_selftest`（`src/tests/core_tests.cpp`）：参数校验、AI 闸门（未知 key/未知选项/需要仓库）、
只读白名单（放行与拒绝各若干）、端点判定（本机/远端/伪装域名）、Key 加密不落明文。
`tools/test-remote.ps1`：选项注入、非法分支名、脏工作区强重置等拒绝条件。
**改动这些路径时必须同步更新断言。**
