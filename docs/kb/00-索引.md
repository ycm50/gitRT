# GitRT 开发知识库 · 索引

这个目录（`docs/kb/`）是**喂给 kb-rag 的仓库开发知识**，与设计文档（`docs/产品设计.md` 等）
分工明确：

| 文档 | 回答什么 |
| --- | --- |
| `docs/产品设计.md` / `docs/技术实现设计.md` | 需求从哪来、设计为什么这样定（**权威**，但很长） |
| `docs/kb/*.md`（本目录） | **"我要改这个仓库，得先知道什么"**：结构、约定、踩过的坑、验证怎么做 |
| `docs/支持矩阵.md` / `docs/改进规划.md` | 某项能力在本机实测到什么程度、还有哪些缺口 |

知识库文件本体在 `.kb/kb.sqlite`（**入库**，随仓库提交）。它是用 kb-rag 引擎把本目录 +
根目录的 `*.md` + `docs/` 下全部 `.md` + `packaging/scripts/使用说明.txt` 切块嵌入后生成的
SQLite。换机器/换人 clone 下来即可直接查，**不需要重建**（连 Python/模型都不需要）。

重建用 `tools/kb-build.ps1`（见下），它会顺带重生成 [06-模块地图](06-模块地图.md)。

**已知局限（换机器时你会看到）**：库里存的是入库时的**绝对路径**（`A:\Downloads\gitRT\...`），
所以别人 clone 之后检索命中里显示的 `path` 仍指向作者机器。检索本身只读库内文本，
**不影响命中与答案**；要看原文就按同名的 `file` 在本仓库里找。

## 怎么查

在 DSH 里用 kb-rag 工具（默认 `kb_root` 就是工作区的 `.kb`）：

- `kb_search({query:"命令表 新增命令 步骤"})` —— 快速检索片段
- `kb_rag({query:"为什么 子菜单 空白 selMask nullptr"})` —— 直接要一段带出处的回答
- `kb_stats({})` —— 看篇数/块数/向量数/健康度

查的时候用**中文术语**（本库正文是中文）：`"PostOwned 泄漏 回收"`、`"windres 依赖 重编译"`、
`"http.proxy 取消代理 空串"` 这类 3–12 个词的术语串最有效；别把整句问题丢进去。

## 怎么重建

```powershell
pwsh -File tools/kb-build.ps1            # 重生成模块地图 + 增量入库 + VACUUM（日常就用这个）
pwsh -File tools/kb-build.ps1 -Force     # 全部重新解析与嵌入（引擎升级、切块规则变了才需要）
pwsh -File tools/kb-build.ps1 -DryRun    # 只重新生成 docs/kb/06-模块地图.md，不动库
```

- 脚本自己找 `~/.dsh/profiles/desktop/node_modules/dsh-kb-rag/kb_engine.py`（dsh-kb-rag 插件自带）；
  挪过位置就用 `-Engine <path>` 指过去。**不把引擎复制进仓库**（两份实现必然漂移）。
- 增量：引擎按 sha256 跳过未变文件，**重复跑是安全的**；只有 `-Force` 才重解析、重嵌入。
- 收尾会 `VACUUM` 压实：库要提交进 git，体积直接进历史。

改完这些文档、或者改了源码里"文件头注释"（[06 模块地图](06-模块地图.md) 的职责文本就是它）
之后跑一次，然后**把 `.kb/kb.sqlite` 一起提交** —— 只改 `docs/kb/*.md` 而不重建，
库里的内容就还是旧的（clone 下来的人搜不到你刚写的东西）。
