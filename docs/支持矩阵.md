## 1. M0 假设清单（对应《产品设计》§3.10）

| # | 假设 | 结论 | 证据 / 下一步 |
| --- | --- | --- | --- |
| **S1** | MinGW-w64 编译的 DLL 能被现代菜单加载 | **成立 [本机]** | ① 两个最致命的加载失败原因已在构建期排除：导出表**只有** `DllGetClassObject` / `DllCanUnloadNow`（`cmake/check_shell_exports.cmake` 强制），且无 `libstdc++-6.dll` / `libwinpthread-1.dll` 依赖；② 注册身份包后 `CoCreateInstance({CLSID})` **成功**，并观察到 `DllHost.exe /Processid:{8E1D2F40-…}` 载入 `C:\Users\…\Programs\GitRT\GitRT.Shell.dll`（`Get-Process dllhost \| %{ $_.Modules }` 证据）。<br>**唯一剩余项**：现代菜单里肉眼可见（[待人工]，见 §4 的人工签核清单）。 |
| **S2** | 开发者模式下可免签名注册（`Add-AppxPackage -Register`） | **成立 [本机]** | `pwsh -File packaging/scripts/dev-install.ps1 -Config Release` → `已注册 GitRT_0.1.0.0_neutral__syvkd2pj3pb86`，`(Get-AppxPackage GitRT).Status = Ok`。**不需要 Windows SDK、不需要证书**。 |
| **S3** | `Directory\Background` / `Drive` 行为符合预期 | **部分成立 [本机]** | 清单注册了 `*` / `Directory` / `Directory\Background`（`Get-AppxPackageManifest` 与 `build\sparse\AppxManifest.xml` 双向确认），**不注册 `Drive`**。<br>**本轮实测到的两个硬性坑**（都会让注册失败）：<br>① `com:Class/@Id` 与 `desktop5:Verb/@Clsid` **必须不带花括号**，否则 `0x80080204 / 0xC00CE169`（已把 CLSID 写进 `identity.json` 时就去括号，并在 `identity.cmake` 里做格式校验）；<br>② 稀疏包目录里的 `AppxManifest.xml` 是**拷贝**，必须每次注册前重新组装，否则会注册到旧清单。<br>**语义缺口**：Shell 对"文件夹上"和"文件夹空白处"传入的 `IShellItem` 都是该目录，两者无法可靠区分 → 实现把"单选一个目录"标记为 `Dir|Bg`，使两种场景得到一致菜单（与 §4.4 要求这两行"都是全量"一致）。真正区分仍待人工在两种位置右键对比。 |
| **S4** | 子菜单的 16 项上限 / 嵌套深度限制 | **已实现保护 [本机]** | 编译期常量 `kMaxItemsPerLevel = 16` + 运行期 `FoldToBudget()`（超限自动折叠进「更多…」子菜单并写 WARN 日志）。当前菜单树最大单层 = **同步组 16 项（含 1 个分隔符）**，恰在上限边界（自检断言"顶层 ≤ 16 项"）。嵌套层是否同样受限仍列 [待人工]。 |
| **S5** | 打包的菜单处理器加载在 `explorer.exe` 还是 `dllhost.exe` | **结论：`dllhost.exe`（代理进程）[本机]** | 实测：激活后出现 `DllHost.exe /Processid:{8E1D2F40-7C3A-4B8E-9F01-2A5C6D7E8F90}`，其模块表里加载了安装目录下的 `GitRT.Shell.dll`。<br>**含义**：§5.1 的"最坏情况（在 Explorer 进程内）"设计是**保守的**——实际由独立代理进程承载，DLL 崩溃不会拖垮资源管理器；`DllMain` 零逻辑、异常兜底、默认日志级别 Warn 等约束继续保留（升级/其他宿主仍可能变化）。 |
| **S6** | 安装/升级/卸载的 Explorer 刷新行为 | **部分成立 [本机]** | 安装 + 重启 explorer 成功（`dev-install.ps1` 全程无错误）；卸载脚本尚未实跑（`dev-uninstall.ps1` 已就绪，需在验证完菜单后执行）。 |

## 2. 场景 × 菜单可见性矩阵（**实现值**）

判定顺序（纯本地、零 git 调用）：选择类型 → `spec.applies` 匹配 → 是否在仓库内 → 配置隐藏项 → 进行中的仓库操作 → 状态快照（Broker 未接入时为"未知"→ 乐观显示）。

| 场景 | 实现行为 | 数据来源 |
| --- | --- | --- |
| 仓库内的文件夹 / 文件夹空白处 | 全量（仅隐藏"初始化仓库"——已经在仓库里了） | 本地廉价探测（`ProbeRepo`） |
| 仓库内的**单个文件** | 只保留：暂存、取消暂存、撤销改动、加入 .gitignore、提交、查看差异、文件历史 | 选择类型位掩码 |
| 多选文件 | 同上（不含文件历史/Blame 之外的目录类命令） | 选择类型位掩码 |
| **非**仓库目录 | 只留：初始化仓库、克隆到此处、打开终端、首选项、自检、AI 助手 | `requiresRepo` 裁剪 |
| 虚拟项（库 / 网络位置 / 控制面板） | 菜单隐藏（`selMask = 0`） | `IShellItem::GetDisplayName` 失败 |
| UNC 网络路径 | 不做任何网络状态查询；仓库相关命令按"未探测到仓库"处理 | `IsNetworkPath` |
| 选区超过 200 项 | 截断（仅用于显示），仍可用 | `kMaxSelection` |
| 合并 / 变基 / cherry-pick / revert / bisect 进行中 | 顶部显示**提示项**（灰显）："⚠ 仓库操作未完成"；并与 `pull / sync / merge / rebase / switch` 灰显（git 自己也会拒绝）；`commit.*` / `查看` / `储藏` 仍可用 | `.git` 下文件存在性（零 git 调用） |
| 未找到 git.exe | 菜单只剩 1 条："未找到 git.exe —— 点击设置路径"（点击打开首选项） | `FindGitExecutable()` |
| 驱动器根目录（`C:\`） | **不注册**（社区实测无效），因此不出现 | 清单未包含 `Drive` |
| 第三方文件管理器（Total Commander 等） | 不可见（只支持传统菜单）——已知缺口，见《产品设计》§3.8 | — |

### 2.1 菜单形态（v0.5 产品决策：只有一个入口）

- 资源管理器右键菜单里**只有一项「GitRT」**：没有子菜单、没有分组、没有命令列表。
- **点击它 = 打开 GitRT 主窗口**，并把窗口的仓库/目录上下文切到你右键的位置（`cmdKey="app.main"`，cmdId=0）。
- git.exe 缺失时，这一项改为把用户送进**首选项**（设置 git 路径），保证还有出口。
- 需要"右键直达命令"的用户可以切回分层菜单：`"menu.mode": "tree"`，此时可选配：
  - `"menu.directTop": ["sync.pull", …]` —— 顶层加速直达命令；
  - `"menu.showFlags": true` —— 组内铺复选/单选开关（点击只改 `config.json` 的 `flags.<cmdKey>.<flagKey>`，不执行 Git）；
  - `"menu.hiddenGroups": […]` / `"menu.hiddenCommands": […]` —— 裁剪菜单（缓解 §3.6 的 16 项上限）。
- tree 形态的树结构：43 项、8 分组、最大深度 2、顶层 10 项（2 条条件提示 + 8 个分组）、无分隔符、无开关项；遍历 ≈ 0.02 ms。

| 安装产物自检 | `"%LOCALAPPDATA%\Programs\GitRT\GitRT.ShellProbe.exe" --self-test …` | **30 通过 / 0 失败 / 0 跳过** |
| 本轮踩到的坑 | — | ① 清单 CLSID 必须**不带花括号**（否则 `0x80080204`）；② 稀疏包目录必须**每次重新组装**（否则注册到旧清单）；③ ★★ 外壳对子菜单项传 `IShellItemArray == nullptr`，按"空选区"裁剪会让**整个子菜单空白**（详见 §4.2） |

### 4.2 ★ 最关键的一条实测发现：外壳不给子项选区

| 项 | 内容 |
| --- | --- |
| 现象 | 现代菜单里 GitRT 的 L1 只出现 8 个带子菜单的分组，**组内完全空白** |
| 定位手段 | ① 给 DLL 加 `GRT_SHELL_PROBE` 调用追踪（记录每个 COM 方法的节点、返回值、`selMask`、`attempted`）；② 给探针加三种模式：`--shell-menu`（让**外壳自己**用 `IContextMenu::QueryContextMenu` 构建菜单，可脚本化复现）、`--activate`（`CoCreateInstance` 走包注册 → dllhost 代理，即**跨进程封送**路径）、`--null-array`（模拟外壳的 nullptr 调用形态） |
| 日志铁证 | `GetState(out) key=cmd.adv.clean → HIDDEN selMask=0 attempted=0` —— `attempted=0` 表示外壳**没有**传数组 |
| 根因 | 外壳顺序是"**先** `EnumSubCommands` 建树 → **再**逐项 `GetState(child, nullptr)`"。原设计假设"子项共享父项解析出的选区"，但父项从未收到数组 → `selMask=0` → `(0 & applies) == 0` → 所有命令 `ECS_HIDDEN` → 子菜单空白 |
| 修复 | ① **选区未知 → 全量显示**（与 §4.3 第 5 步"状态未知→乐观显示"同源，真正的闸门交给 GUI 参数面板）；② **进程内粘性选区**：同一次菜单调用里外壳只要给过任何一次真实数组（通常发生在根项），就记住它（TTL 5 s）供后续 nullptr 调用复用；③ "操作进行中"提示项只在确知进行中时显示 |
| 回归测试 | `tools/test-all.ps1` 的 **D4**（`--activate --null-array`：要求子项仍可见）与 **D5**（`--shell-menu`）。**这两个用例是本次事故的直接产物**：纯进程内测试（`--self-test` / `--dump`）永远看不到这个 bug |
| 顺带修正 | `GetCanonicalName` 现在为每个节点返回**稳定且唯一**的 GUID（根节点保持既有规范名），不再对子项返回 `GUID_NULL`。按 §4.2 本就该如此，但**它不是本次症状的已证实原因**（已证实的只有上面的选区问题） |
| 尚存降级 | 若外壳**从不**给数组（某些宿主/调用路径），菜单会退化为"不做选区裁剪"（文件与目录的差异不再体现）。后续可用文档化的 `IServiceProvider`（`SetSite` → `SID_STopLevelBrowser` → `IShellView::GetItemObject(SVGIO_SELECTION)`）主动取选区，彻底摆脱对入参的依赖 |

### 4.1 人工签核清单（§13.3 中不可自动化的部分）

| # | 步骤 | 期望 |
| --- | --- | --- |
| 1 | 在任意 Git 仓库目录（如 `A:\Downloads\git-right-type`）**空白处右键** | **现代菜单第一层**（不需要点"显示更多选项"）出现「GitRT」，带子菜单箭头 |
| 2 | 展开 GitRT | 顶部 4 条高频直达（提交/拉取/推送/状态面板）+ 分隔符 + 8 个分组 |
| 3 | 展开「同步」 | 命令项 + 分隔符 + 复选/单选开关（「拉取 · 使用变基 (--rebase)」应为勾选态） |
| 4 | 点一个**开关**（如「推送 · 包含标签」） | 菜单关闭、复选态在下次打开时保持；**不产生任何 git 操作**；`%APPDATA%\GitRT\config.json` 出现 `flags.sync.push.tags` |
| 5 | 点「推送」 | GitRT 窗口打开，参数面板已预填选区与开关状态，命令行预览可见可复制 |
| 6 | 选中一个**文件**右键 → GitRT | 只剩文件相关命令（暂存/撤销/提交/差异/文件历史），不含拉取/推送 |
| 7 | 在**非仓库**目录（如 `C:\Windows\Temp`）右键 | 只剩：初始化仓库、克隆到此处、打开终端、首选项、自检、AI 助手 |
| 8 | 卸载（`dev-uninstall.ps1`）后重启 explorer | 菜单消失，无残留（见 §11.5 残留清单） |

> 若第 1 步没出现：先按 §2.7 路径 A（`tools/dev/register-legacy.ps1` + 「显示更多选项」）确认"实现正确"，再单查注册链路（本文件 §4 已给出可脚本化的注册证据，可用于定位是"注册"还是"菜单渲染"的问题）。
